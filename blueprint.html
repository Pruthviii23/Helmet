System overview

Sheet 01 / 08

Two separate boards with no wire between them. The helmet only ever says one thing, "WORN". The bike never waits for "not worn". It just drops the relay when the pings stop.

Helmet unit schematic

Sheet 02 / 08

The pressure pad and R1 form a voltage divider. The ADC reads near 0 V with no head and climbs when the pad is squeezed. The Hall sensor pulls GPIO4 low when the strap magnet sits in front of it.

All ground symbols join at the SuperMini GND pin.

RS1 + R1 divider

Either leg of the FSR to 3V3, the other to GPIO3. R1 goes from GPIO3 to GND. Use GPIO0–4 only for analog, since those are the C3's ADC1 pins.

U3 Hall

A bare 3-pin A3144 is open-collector. The firmware turns on the internal pull-up, so no extra resistor is needed. Modules like KY-003 already have one.

Power

Use a TP4056 board with protection (it has separate B± and OUT± pads). OUT+ goes through SW1 to the SuperMini 5V pin. The onboard regulator runs fine from 3.4–4.2 V.

Programming

Turn SW1 off before you plug USB into the helmet SuperMini, so the USB 5 V can't push back into the charger and cell.

Bike bench schematic

Sheet 03 / 08

Your relay is a bare relay with no driver board. A GPIO pin can only give about 20 mA at 3.3 V, and the coil wants around 70 mA at 5 V. Q1 does the switching. The solenoid sits on its own 12 V loop through the relay contacts, and S1 plays the bike's START button.

Every ground symbol is one net. The 12 V negative, the buck's GND and the SuperMini GND must be joined.

Q1 driver

GPIO5 HIGH puts about 2.6 mA into Q1's base through R2, which is plenty to saturate it. R3 holds the base low while the board boots, so the relay can't click on by itself.

D1 + D2 flyback

Coils kick back a voltage spike when switched off. Each diode sits across its coil with the striped end (cathode) toward the + side. Without D1, Q1 or the SuperMini can die.

S1 START

S1 carries the full solenoid current, so it must be rated for it (a 3 A panel button, not a tiny tactile switch). Solenoid fires only when the helmet is on and you press START, like a real bike.

Other voltages

12 V relay coil: wire K1's top to +12V instead of +5V, nothing else changes. 5 V or 6 V solenoid: match J1 to the solenoid's voltage, keep the buck for logic.

Physical layout

Sheet 04 / 08

Where each part lives. The pad goes where your head actually presses, the electronics stay out of the impact zone at the back, and the Hall sensor and magnet only meet when the buckle is fully latched.

Bench plan is schematic. Keep the 12 V wires short and twisted together, away from the SuperMini's antenna end.

Finding K1's pins

Multimeter on ohms. The two pins showing about 70 Ω are the coil. Of the other three, the pair that beeps is COM and NC. The remaining one is NO.

Q1 pinout

2N2222 / 2N3904 flat face toward you, legs down: E, B, C. BC547 is C, B, E. Check your part's datasheet if unsure.

Pins to avoid

GPIO2, GPIO8 and GPIO9 control how the SuperMini boots. Leave them unconnected.

helmet.ino
#include <WiFi.h>
#include <esp_now.h>

const int PAD_PIN  = 3;     // RS1 + R1 divider (ADC)
const int HALL_PIN = 4;     // U3 OUT, LOW = magnet near
const int PAD_THRESHOLD = 1000; // tune on sheet 08, step 06

// Paste the MAC the bike board prints at boot
uint8_t bikeMac[] = {0x00,0x00,0x00,0x00,0x00,0x00};

void setup() {
  Serial.begin(115200);
  pinMode(HALL_PIN, INPUT_PULLUP);
  analogReadResolution(12);       // 0..4095

  WiFi.mode(WIFI_STA);
  WiFi.setTxPower(WIFI_POWER_8_5dBm);  // SuperMini fix, sheet 06
  delay(100);
  Serial.print("Helmet MAC: ");
  Serial.println(WiFi.macAddress());

  esp_now_init();
  esp_now_peer_info_t peer = {};
  memcpy(peer.peer_addr, bikeMac, 6);
  peer.channel = 0;
  peer.encrypt = false;
  esp_now_add_peer(&peer);
}

void loop() {
  int  pad     = analogRead(PAD_PIN);
  bool headIn  = pad > PAD_THRESHOLD;
  bool clicked = digitalRead(HALL_PIN) == LOW;

  Serial.printf("pad=%d head=%d strap=%d\n", pad, headIn, clicked);

  if (headIn && clicked) {
    const char msg[] = "WORN";
    esp_now_send(bikeMac, (const uint8_t*)msg, sizeof(msg));
  }
  delay(500);
}
bike.ino
#include <WiFi.h>
#include <esp_now.h>

const int RELAY_PIN = 5;          // to R2 → Q1 base
const unsigned long TIMEOUT_MS = 1500;

// Paste the MAC the helmet board prints at boot
uint8_t helmetMac[] = {0x00,0x00,0x00,0x00,0x00,0x00};

volatile unsigned long lastPing = 0;
volatile bool everPinged = false;   // stay locked at boot

// esp32 core 3.x signature
void onRecv(const esp_now_recv_info_t *info,
            const uint8_t *data, int len) {
  if (memcmp(info->src_addr, helmetMac, 6) != 0) return;
  if (len >= 4 && memcmp(data, "WORN", 4) == 0) {
    lastPing = millis();
    everPinged = true;
  }
}

void setup() {
  pinMode(RELAY_PIN, OUTPUT);
  digitalWrite(RELAY_PIN, LOW);        // locked
  Serial.begin(115200);

  WiFi.mode(WIFI_STA);
  WiFi.setTxPower(WIFI_POWER_8_5dBm);  // SuperMini fix, sheet 06
  delay(100);
  Serial.print("Bike MAC: ");
  Serial.println(WiFi.macAddress());

  esp_now_init();
  esp_now_register_recv_cb(onRecv);
}

void loop() {
  bool unlocked = everPinged &&
                  (millis() - lastPing < TIMEOUT_MS);
  digitalWrite(RELAY_PIN, unlocked ? HIGH : LOW);
  delay(20);
}

Why only "WORN"

If the bike waited for a "removed" message, a dead battery would leave it unlocked forever. Silence means locked, so every failure is safe.

Lower the radio power

Tested on the real boards: at full power one SuperMini's messages never arrived. Setting WIFI_POWER_8_5dBm fixed it, with every message acknowledged. Keep that line in both sketches.

Older board package

On esp32 core 2.x the receive callback is onRecv(const uint8_t *mac, const uint8_t *data, int len). Compare mac instead of info->src_addr.

Bring-up + safety

Sheet 08 / 08

Build and test in this order. Each step checks one thing, so when something fails you know where to look.

  1. Set the buck to 5.0 V

    Power U1 from J1 with nothing on its output. Turn the trim screw until the multimeter reads 5.0 V.

    pass: 4.9–5.1 V
  2. Identify K1's pins

    Use the multimeter method on sheet 05. Mark COM and NO with a pen.

    pass: coil ≈ 70 Ω, COM–NC beeps
  3. Read both MAC addresses

    Flash bike.ino and helmet.ino over USB. Each prints its MAC in the Serial Monitor. Paste each one into the other sketch and flash again.

    pass: two MACs written down
  4. Test the driver, no solenoid yet

    Wire U1, U2, R2, R3, Q1, D1 and K1. Temporarily change digitalWrite(RELAY_PIN, LOW) in setup to HIGH.

    pass: relay clicks at power-up
  5. Add the solenoid loop

    Wire F1, S1, K1 contacts, L1 and D2. With the relay still forced on, tap START. Then put the LOW back.

    pass: plunger fires on each tap
  6. Tune the pressure pad

    Wire the helmet. Watch pad= in the Serial Monitor with the helmet off and on your head. Set PAD_THRESHOLD halfway between the two.

    pass: head=1 only when worn
  7. Check the strap

    Latch and unlatch the buckle. If strap= never changes, flip M1 or bring it closer to U3.

    pass: strap=1 only when latched
  8. Full run

    Wear it and latch it, then press START. Unlatch it and press START again after two seconds. Then switch the helmet off and try once more.

    pass: fires only while worn and latched

Never from a pin

Don't connect K1's coil or L1 directly to a GPIO pin. The pin can't supply the current and the kickback will kill the board.

Solenoid heat

Most small solenoids are rated for short pulses. Holding one on for minutes cooks it. S1 keeps each fire short, like a starter.

Common ground

The 12 V side and the 5 V side share one GND. If the relay never clicks, check this before anything else.

Moving to a real bike

K1 goes in the thin wire from the handlebar START button to the starter relay, never in the thick starter motor cable. Power U1 from the bike's switched 12 V.
